# layer1 / layer2-5 论文级架构提炼

## 1. 文档目的

本文档不再停留在“方法论口号”层面，而是直接基于当前 `layer1` 与 `layer2-5` 的 HLS 代码、关键综合快照和已有架构图，回答 3 个问题：

1. `layer2-5` 当前已经做成了什么样的结构化硬件骨架。
2. 这些结构在论文中应该怎样被组织成“看起来高级且站得住脚”的论述。
3. `layer1` 当前最大的瓶颈是什么，以及它最适合如何用相同的方法论继续推进。

本文的核心目标是把“代码里的真实结构”上升为“论文里的架构贡献表述”，避免停留在“只是做了几条 pragma 优化”的低层叙述。

## 2. 当前代码所体现的总体架构

从实现方式看，`layer2-5` 和 `layer1` 都已经不再是传统意义上的“直接在顶层张量上展开卷积并即时写回”的写法，而是逐步演化为一条分阶段片上数据流。

以 `layer2-5` 为例，当前主流程已经清晰收束为：

```text
stage_input
-> pad_ico
-> init_output_tiles
-> main_conv / partial_sum
-> post_process
-> writeback
```

这条骨架在代码中对应：

1. `stage_input_frame_quantized()`
2. `pad_ico_quantized()`
3. `init_output_tiles()`
4. `ri_partial + output_tile` 主计算路径
5. `post_process_output_tiles()`
6. `writeback_output_tiles()`

对应代码位置：

- `hls_src/HLS/layer2-5/ico_conv_layer2_5.cpp`
- 入口函数 `conv_ico_layer2_5(...)`

而 `layer1` 也已经具备同一骨架的雏形：

1. `stage_input_frame()`
2. `pad_ico()`
3. `init_output_tiles()`
4. `ri_partial + ro_accum + output_tile`
5. `post_process_output_tiles()`
6. `writeback_output_tiles()`

对应代码位置：

- `hls_src/HLS/layer1/ico_conv_layer1.cpp`
- 入口函数 `conv_ico_layer1(...)`

因此，当前最重要的判断应明确写成：

`现有工作已经从“逐层功能实现”演进为“面向球面 ConvIco 的阶段化片上数据流架构”。`

## 3. layer2-5：已经形成的论文级结构

## 3.1 输入准备与主计算解耦

在 `layer2-5` 中，输入并不是直接送入主卷积循环，而是先经历：

1. 输入 staging
2. `PadIco` 与重排映射
3. 填充帧生成

在代码中，这对应：

- `stage_input_frame_quantized()`：先把顶层输入搬到 `staged_input`
- `pad_ico_quantized()`：在局部缓冲上完成几何重排、极点统计与填充
- `padded_frame`：作为后续主卷积的规则化输入来源

这意味着你当前并不是“边卷积边处理球面邻接”，而是把不规则输入准备前移，形成独立输入准备子系统。

论文中的高级写法可以是：

`针对二十面体卷积中邻域访问不规则、极点处理耦合主计算路径的问题，构建输入准备子系统，将输入 staging、几何重排、极点补值和填充帧生成前移到独立阶段，使后续卷积核心在规则局部窗口上执行。`

这条表述的价值在于：

1. 它把 `PadIco` 从“辅助函数”上升为“输入准备架构”。
2. 它能解释为什么当前优化重点是先解决访存结构，而不是先堆并行乘加。
3. 它与后续 `layer1` 的方法迁移天然连贯。

## 3.2 紧凑权重组织与按需展开

当前 `layer2-5` 没有直接保存永久性的完整 `3x3` 展开核，而是：

1. 保留紧凑的 `7-neighbor` 权重表示；
2. 使用 `kernel_expansion_idx` 在局部阶段恢复为 `3x3` MAC 所需布局；
3. 通过 `load_expanded_kernel()` 把局部展开前移到 `kernel_tile` 装载阶段。

这在代码中对应：

- `expanded_weight_at()`
- `load_expanded_kernel()`
- `kernel_tile[OC_TILE][KERNEL_H][KERNEL_W]`

因此，这不是单纯的“做了一个索引函数”，而是一个明确的参数组织策略。

论文中的高级写法可以是：

`针对球面卷积有效邻域仅包含 7 个方向的结构特征，采用紧凑权重组织与索引驱动的按需展开策略，替代全尺寸 3x3 核缓存，以降低参数存储和深层 MAC 路径中的权重访存压力。`

这条表述的价值在于：

1. 它把“节省 BRAM”的工程现象提升为“面向几何稀疏邻域的参数表达方法”。
2. 它非常适合写成当前硬件创新点之一。

## 3.3 局部部分和驱动的 tile 化累加

`layer2-5` 当前最核心的结构变化，不是某一条 `PIPELINE`，而是你已经把累加路径改成：

```text
conv
-> ri_partial
-> ci_sum
-> output_tile
```

在代码中，对应：

1. 每个 `ri` 上的卷积结果先写入 `ri_partial`
2. 再在 `ri` 维上局部归并为 `ci_sum`
3. 最后再写回 `output_tile`

对应关键数组：

- `ri_partial[OC_TILE][RIN][CHARTS][H][W]`
- `output_tile[OC_TILE][ROUT][CHARTS][H][W]`

论文中的高级写法可以是：

`针对多维卷积累加导致的输出更新依赖，采用局部部分和驱动的 tile 化累加结构，将旋转维与输入通道维上的累加过程限制在片上局部缓冲内完成，避免全局输出张量上的高频读改写依赖。`

这条表述很关键，因为它把你的工作从“本地数组优化”提升为“部分和组织策略”。

## 3.4 输出收尾阶段化

当前 `layer2-5` 已明确拆出：

1. `post_process_output_tiles()`
2. `writeback_output_tiles()`

并引入：

- `output_tile`
- `output_post`

这说明输出路径已经从“边后处理边写回”的混合逻辑，转成了带明确边界的收尾阶段。

论文中的高级写法可以是：

`针对球面卷积输出端极点修正、平滑和最终写回之间的控制耦合，将输出路径拆分为局部后处理阶段与统一写回阶段，并通过中间输出 tile 缓冲建立清晰的结构边界。`

这条表述的价值在于：

1. 你不只是“把函数拆成两个”。
2. 你是在构建一个完整的数据流尾部边界。
3. 这与整个阶段化架构是统一的。

## 3.5 共享参数化主干块

从 `layer2-5` 的结构重复性看，它已经可以被明确写成“共享参数化主干块”，而不是单层实验代码。

可以直接使用的高级表述是：

`针对 layer2-5 在通道规模、旋转维和空间分辨率上的一致性，本文将其统一抽象为共享参数化 ConvIco 主干块。该主干块由输入准备子系统、紧凑权重展开子系统、共享窗口 MAC 计算核心、局部输出 tile 累加单元以及输出收尾单元构成，从而形成一套面向该网络结构特征的数据流与存储协同硬件架构。`

这句话和你现有架构图是完全一致的，不是“硬拔高”。

## 5. layer1：当前真正的结构瓶颈

如果只看 `layer1` 的综合快照，很容易把问题说成“II 还是没压下来”。这不够高级，也不够准确。

结合代码和已有关键快照，`layer1` 的真实结构现状应写成：

### 5.1 主乘加路径其实已经基本跑通

从以下快照可以看到：

- `hls_src/layer0-1_details/2026-04-07_175100_layer1_partial_key.md`
- `hls_src/layer0-1_details/2026-04-07_192256_layer1_partial_key.md`

当前明确结论是：

1. `ri_partial` 主计算环已经做到 `Final II = 1`
2. 当前“综合很慢”的核心原因不在主乘加路径

这意味着：

`layer1` 当前的最大问题不是算力不够，也不是最深卷积主环本身还没打通，而是输出归并结构没有彻底阶段化。`

### 5.2 热点已经从 output_tile 迁移到 ro_accum

代码里当前的主要归并路径是：

1. 先把 `output_tile` 拷到 `ro_accum`
2. 再做 `ro_accum + ri_partial` 的归并
3. 再把 `ro_accum` 写回 `output_tile`

对应数组：

- `output_tile`
- `ro_accum`
- `ri_partial`

这条路径在 `2026-04-07_175100_layer1_partial_key.md` 中先表现为：

- `ri_partial -> output_tile` 的原位归并热点

随后在 `2026-04-07_192256_layer1_partial_key.md` 中变成：

- `ro_accum` 上的 carried dependence 热点

这说明结构方向是对的，但新的归并缓冲仍同时承担了：

1. 初值保持
2. 部分和累加
3. 回写目标

因此它还没有彻底切断：

`load -> reduce -> store back to same array`

这条依赖链。

### 5.3 PadIco 仍是第二热点

`layer1` 的 `PadIco` 仍然保留了：

- 极点统计
- 重排映射
- 填充写回

在同一个大函数内完成的组织方式。

虽然已经加入 `staged_input`，但从快照看：

- `PadIco` 的历史依赖问题仍在
- 它已经不再是唯一热点，但依然是后续结构优化主线之一

因此，`layer1` 的论文级问题表述应写成：

`layer1` 当前的主要瓶颈不是主卷积乘加，而是输入准备与输出归并两侧的结构相关依赖：前者表现为 `PadIco` 中不规则访问与极点统计耦合，后者表现为归并阵列同时承担状态保持与更新职责，从而在同一 pipeline 内形成 carried dependence。`

## 6. 用方法论处理 layer1：最值得做的 4 个方向

## 6.1 把归并从“两级数组回写”改成“分层归并”

当前 `layer1` 更像：

```text
ri_partial
-> ro_accum
-> output_tile
```

更适合的下一步应是：

```text
ri_partial
-> ri_reduced
-> co_tile_accum
-> output_tile
```

其中：

- `ri_reduced`：先只解决 `ri` 维归并
- `co_tile_accum`：再解决跨 `ci_tile` 的累加

这条改法的本质不是“多加一个数组”，而是：

`把不同维度的归并拆成两个生命周期不同的阶段，避免在同一缓冲上同时完成状态保持和更新。`

对应的论文表达可以是：

`采用分层局部归并策略，将旋转维归约与跨输入通道 tile 的累加过程解耦，以削弱归并阶段的 load-store carried dependence。`

## 6.2 把 base_tile 和 acc_tile 分开

当前 `ro_accum` 既承担 base value，又承担活动累加值。

更合理的结构应是：

- `base_tile`：只读，保存 bias 或上一阶段初值
- `acc_tile`：只负责当前活动部分和累加
- 最终再做 `output_tile = base_tile + acc_tile`

这条改法的本质是：

`把“状态保持阵列”和“活动累加阵列”解耦。`

这比继续在 `ro_accum` 上抠 pragma 更像真正的架构优化。

## 6.3 把 PadIco 拆成 3 个子阶段

当前最值得推进的是：

1. 极点统计
2. 重排搬运
3. 填充帧生成

三段显式分开。

这样做的意义不是代码更漂亮，而是：

1. 更容易单独分析每一段的端口需求
2. 更容易插入更细粒度输入 staging
3. 后续更容易做 bank 化或双缓冲

论文里可以写成：

`针对 PadIco 中极点统计与重排访问耦合导致的端口冲突，将输入准备过程拆分为极点统计、重排搬运和填充帧生成三个子阶段，从而降低主计算核前端的不规则访存压力。`

## 6.4 保持“先结构化，再定点化”的顺序

`layer2-5` 的经验已经很明确：

1. 先把数据流骨架做对
2. 再引入 `ap_fixed`
3. 再围绕资源和数值误差做精修

因此 `layer1` 最合适的推进顺序不是：

`先量化 -> 再看结构`

而应是：

`先切断归并依赖 -> 再局部引入混合精度 -> 再做资源收束`

这点很适合写进方法章节，作为你整个硬件线的一条统一设计原则。

## 7. 适合直接写进论文的总结句

下面这些句子基本可以直接进入论文草稿。

### 7.1 关于 layer2-5

`针对 layer2-5 在通道规模、旋转维和空间分辨率上的一致性，本文将其统一抽象为共享参数化 ConvIco 主干块，并构建由输入准备、紧凑权重展开、共享窗口 MAC、局部部分和累加以及输出收尾组成的阶段化片上数据流架构。`

### 7.2 关于紧凑权重展开

`针对球面卷积有效邻域仅包含 7 个方向的结构特征，本文采用紧凑权重表示与索引驱动的按需展开策略，避免深层卷积中永久性全尺寸 3x3 核缓存带来的额外存储与访存开销。`

### 7.3 关于局部部分和

`针对多维累加导致的输出更新依赖，本文采用局部部分和驱动的 tile 化累加结构，将旋转维与输入通道维上的累加过程限制在片上局部缓冲内完成，从而降低顶层输出张量上的高频读改写相关。`

### 7.4 关于 layer1 当前瓶颈

`layer1 当前的主要结构瓶颈不在主卷积乘加路径，而在输入准备与输出归并两侧的依赖链：前者表现为 PadIco 中不规则访问与极点统计耦合，后者表现为归并阵列同时承担状态保持与更新职责，从而在同一 pipeline 内形成 carried dependence。`

### 7.5 关于 layer1 下一步

`后续 layer1 的优化重点不是继续对单一循环做 pragma 微调，而是通过分层局部归并、基值保持与活动累加解耦，以及输入准备子阶段拆分，进一步将热点从数组原位归并转化为可调度的阶段化片上数据流。`

## 8. 当前最推荐的执行顺序

1. 把本文中的 `layer2-5` 结构表述吸收到硬件主文档和毕设章节中，先把已有工作“说高级”。
2. `layer1` 先不急着量化，优先重构：
   - `ri_partial -> ri_reduced -> co_tile_accum`
   - `base_tile + acc_tile`
3. 再拆 `PadIco` 的输入准备子阶段。
4. 结构稳定后，再决定是否把 `layer1` 迁移到与 `layer2-5` 一致的混合精度骨架。

这样可以保证：

- `layer2-5` 先承担“已经完成的论文级架构创新”；
- `layer1` 再承担“当前最值得继续推进的结构性瓶颈处理”；
- 两者最终收束成一条统一的硬件创新主线。
