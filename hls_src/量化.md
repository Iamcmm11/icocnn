量化
1. int8
int8 是最直观的：每个数用 8 bit 存。
如果 signed int8：可存编号：-128 ~ 127   共 256 档
例子：
scale = 0.05
x = 1.23
q = round(1.23 / 0.05) = 25
还原 = 25 * 0.05 = 1.25
误差是 0.02。
scale = 0.2
q = round(1.23 / 0.2) = 6
还原 = 6 * 0.2= 1.2
误差 = |1.23 - 1.2| = 0.03
scale 是 float 和 int8 之间的换算单位，相当于 int8 的步长。它决定了量化的范围和精度：scale 小则精度高但范围窄，scale 大则范围宽但精度低。
2. W4
W4 一般指 weights 4-bit，也就是模型权重量化到 4 bit。
4 bit 只有 2^4 = 16 档，常见 signed 范围类似：
-8 ~ 7
比如某组权重的 scale = 0.1：
x = 0.63
q = round(0.63 / 0.1) = 6
还原 = 0.6
如果 x = 1.2：
q = round(1.2 / 0.1) = 12
但 4-bit signed 最大只能到 7，所以会被截断：
q = 7
还原 = 0.7
所以 W4 很省显存，但比 int8 更容易丢精度。通常会按 group 存 scale，比如每 32/64/128 个权重共用一个 scale。
3. KV8
KV8 指 Transformer 里的 KV cache 用 8 bit 存。
大模型生成文本时，会缓存每一层的 Key/Value。上下文越长，KV cache 越大。KV8 就是把这些缓存从 FP16/BF16 压到 8 bit。
数学上仍然类似：
K_float -> K_int8
V_float -> V_int8
例子：
scale = 0.01
K = -0.374
q = round(-0.374 / 0.01) = -37
还原 = -0.37
它主要省的是长上下文推理时的显存，不一定压模型权重本身。
4. A12
A12 一般指 activation 12-bit，也就是中间激活值用 12 bit。
12 bit 有：
2^12 = 4096 档
比 int8 的 256 档细很多，所以误差更小，但也更占空间。
比如 signed 12-bit 大概是：
-2048 ~ 2047
假设 activation 范围大概是 [-6, 6]：
scale = 6 / 2047 ≈ 0.00293
x = 3.14159
q = round(3.14159 / 0.00293) ≈ 1072
还原 ≈ 1072 * 0.00293 ≈ 3.14
所以 A12 比 A8 精细不少，常用于想保住激活精度的地方。
5. MX6 / MX9
MX 不是普通 int 量化，而是 microscaling / shared microexponent 一类格式。直觉上是：
一小块数字共用一个大 scale
每个数字自己再存一个很短的值
有时还有子块 sub-scale
普通 int8 是：
每个数：q
一组数：共用 scale
x ≈ scale * q
MX6/MX9 更像：
x ≈ block_scale * subblock_scale * q
其中：
block_scale：一大块共用
subblock_scale：更小的子块共用
q：每个数自己的低 bit 表示
MX6 可以理解为平均每个值约 6 bit。
MX9 可以理解为平均每个值约 9 bit。
注意是“平均”，因为 scale 是一组数共享的，分摊到每个数上。
举个非常简单的例子。假设一组数：
[0.9, 1.0, 0.08, 0.07]
普通 per-group 量化如果用一个 scale，要照顾 1.0 这种大数，小数 0.08、0.07 可能会很粗。
1.0  -> round(10)   -> 10
0.9  -> round(9)    -> 9
0.08 -> round(0.8)  -> 1
0.07 -> round(0.7)  -> 1
MX 会说：
前两个数：用正常 sub-scale
后两个数：用更小 sub-scale
这样小数也能用更细的格子表示。它的好处是：比普通低 bit int 更灵活，比完整 float 更省。

MX6：更省，误差更大
MX9：更贵，误差更小
如果用同一个值 0.73 类比：
MX6 可能只能还原成 0.75
MX9 可能能还原成 0.7305
