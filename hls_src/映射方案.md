一、当前 FPGA 神经网络加速的主流映射方案（按落地度排序）
从工业界落地和学术研究的主流趋势来看，核心集中在以下 4 类（覆盖 80% 以上的实际应用场景），且均适配纯 FPGA 的硬件特性：
1. 部分映射（Partial Mapping）—— 纯 FPGA 最核心的主流方案
核心地位：纯 FPGA 场景下的第一主流方案，云端 / 边缘端均广泛落地（如 AWS F1、阿里云 FPGA 加速卡、边缘纯 FPGA 推理盒）。
适配逻辑（纯 FPGA）：
纯 FPGA 无片上 CPU，需通过PCIe/10G 以太网 / AXIe 等接口与外部 CPU / 服务器交互：
外部 CPU 负责：网络控制逻辑、数据预处理（归一化、格式转换）、后处理（Softmax、结果解析）；
纯 FPGA 仅负责：计算密集型算子（卷积、矩阵乘、池化），最大化利用 FPGA 的 DSP/BRAM 资源。
典型场景：ResNet、YOLO 等中大型 CNN 推理，纯 FPGA 作为 “计算加速卡” 挂载到服务器。
2. 空间并行 + 分块映射（Spatial Parallel + Tile Mapping）—— 高性能场景首选
核心地位：纯 FPGA 实现高吞吐的 “标配组合方案”，是云端大算力需求的主流选择。
适配逻辑（纯 FPGA）：
空间并行：在纯 FPGA 上部署多组同构 MAC 阵列（如 128/256 路 MAC 并行），同时处理特征图的不同通道 / 像素点；
分块映射：将超大特征图 / 权重切分为适配纯 FPGA 片上 BRAM 的小分块，避免片外 DDR 访存瓶颈，分块计算完再拼接结果。
关键优势：纯 FPGA 无 ZYNQ 的 ARM 核资源占用，可将全部逻辑资源投入到并行计算单元，吞吐比 ZYNQ 高 30%~50%。
典型场景：数据中心的批量图像分类、视频流实时检测。
3. 层流水映射（Layer Pipeline Mapping）—— 边缘低延迟场景主流
核心地位：边缘纯 FPGA（如 XC7Z020/XCZU9EG）实现低延迟推理的主流方案。
适配逻辑（纯 FPGA）：
将网络的核心层（卷积→BN→ReLU→池化）拆解为流水线硬件模块，模块间通过纯 FPGA 的片上流接口（如 AXI-Stream）直连，数据无需回传片外，端到端延迟可低至 μs 级。
纯 FPGA 适配要点：无需考虑 ZYNQ 的 ARM 与 FPGA 的交互延迟，流水线的 “启动间隔（II）” 可做到 1，理论吞吐接近硬件极限。
典型场景：工业视觉、自动驾驶的实时目标检测（要求 < 10ms 延迟）。
4. 时分复用映射（Time-Division Mapping）—— 低端纯 FPGA 的主流选择
核心地位：资源受限的纯 FPGA（如 XC7A35T 等入门级芯片）的唯一主流方案。
适配逻辑（纯 FPGA）：
仅设计一套通用计算单元（如 16 路 MAC），通过控制逻辑分时处理不同层 / 不同卷积核的计算任务，用 “时间换空间”，适配低端纯 FPGA 的资源限制。
典型场景：智能家居、物联网端的轻量级网络（如 MobileNet、TinyYOLO）推理。
