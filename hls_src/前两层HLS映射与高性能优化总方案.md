## 2. 总体映射思路

结合 `hls_src/映射方案.md` 中对 FPGA 神经网络主流映射方式的归纳，可以将本项目的前两层实现理解为一个逐步演进的过程：

1. `layer0` 采用“部分映射 + 部分融合”的实现方式。
2. `layer1` 在 `layer0` 的基础上继续向“分块流式 + 紧凑权重表示”演进。
3. 最终面向整网高性能实现时，应采用“部分映射 + 空间并行 + 分块流式 + 层间流水”的混合架构。

从论文角度看，这一过程具有明确的技术递进关系：

1. 第一阶段解决“功能正确、数据对齐、HLS 可综合”问题。
2. 第二阶段解决“中间缓冲过大、片上存储超限”问题。
3. 第三阶段解决“深层卷积在纯 FPGA 上的高性能映射”问题。

因此，前两层不是两个孤立实验，而是最终高性能架构的两个连续台阶。

## 3. Layer0 的优化总结

## 3.1 Layer0 的原始特征

`layer0` 的输入规模较小：

1. `Cin = 1`
2. `Rin = 1`
3. 输出通道 `Cout = 32`
4. 输出旋转通道 `Rout = 6`

因此，`layer0` 的主要难点并不在乘加次数本身，而在于：

1. icosahedral padding 与顶点平滑的特殊数据访问模式
2. Python 参考实现与 C/HLS 实现之间的逐层对齐
3. 为便于验证而保留的中间缓冲对 BRAM 的消耗

换言之，`layer0` 的工程重点更偏向“正确实现特殊拓扑卷积”和“控制中间数据组织成本”。

## 3.2 Layer0 的优化主线

`layer0` 的优化并不是一开始就以极限性能为目标，而是先保证验证链路完整，再逐步移除高成本中间缓冲。其优化主线可以概括为：

1. 保留完整中间层，确保 Python 与 C 端可逐层对齐。
2. 去除大中间缓冲，缩减 BRAM。
3. 将卷积路径改为直接读取 `padded_frame`，减少数据重排。
4. 将输出端改为原位处理，减少输出缓存复制。

被移除或压缩的关键中间缓冲包括：

1. `conv_output`
2. `output_frame`
3. `input_frame`
4. `reshaped_input`
5. `kernel_2d`
6. `bias_2d`

这一步的核心价值在于：

1. 把 HLS 实现从“验证型结构”转为“可综合、可落地结构”
2. 让后续 `layer1` 的实现可以直接参考一套已经被验证过的部分融合数据流

## 3.3 Layer0 的结果

根据当前已稳定的 `layer0` 基线结果：

1. Estimated Clock：`4.498 ns`
2. Latency：`2001222 cycles`
3. BRAM_18K：`20 / 890`
4. DSP：`45 / 840`
5. FF：`13725 / 407600`
6. LUT：`13906 / 203800`

功能验证结果：

1. Max Error：`9.53674e-07`
2. RMSE：`7.03355e-08`
3. 结论：`PASS`

这说明 `layer0` 已经达到了一个很好的平衡点：

1. 结构清晰，便于调试
2. 资源很低，不构成整板瓶颈
3. 作为后续层设计的参考模板足够稳定

## 4. Layer1 的优化总结

## 4.1 Layer1 与 Layer0 的本质差异

`layer1` 与 `layer0` 的根本区别在于乘加规模和权重展开规模急剧增长。

相对于 `layer0`：

1. `Cin` 从 `1` 增长到 `32`
2. `Rin` 从 `1` 增长到 `6`
3. 每个输出点的有效邻域乘加项从 `7` 增长到 `32 x 6 x 7 = 1344`

因此，仅从计算量看，`layer1` 相比 `layer0` 大约增加：

1. `32 x 6 = 192` 倍的输入通道相关计算规模

这也是为什么不能把 `layer0` 的结构不加区分地按比例放大到 `layer1`。在 `layer0` 中不显著的问题，一旦进入 `layer1`，就会被放大成片上存储瓶颈。

## 4.2 Layer1 的第一轮实现：沿用 Layer0 的部分融合思路

`layer1` 的第一轮 HLS 结构，本质上是将当前优化后的 `layer0` 思路迁移到更高维输入上：

1. 去掉 `input_frame`
2. 去掉 `reshaped_input`
3. 去掉 `kernel_2d`
4. 去掉 `bias_2d`
5. 直接在 `padded_frame` 上卷积

这一步是必要的，因为它延续了 `layer0` 已验证的数据流，并能快速得到一个功能正确、可综合的 `layer1` 版本。

但是这一轮综合结果显示出一个非常关键的问题：

1. BRAM_18K：`1344 / 890`
2. 利用率：`151.01%`

这意味着第一轮 `layer1` 虽然功能正确，但在资源上完全不可落地。

## 4.3 Layer1 的核心瓶颈：完整 kernel 展开缓存

通过 `conv_ico_layer1_csynth.rpt` 的 Memory 表分析，可以明确定位瓶颈：

1. 完整 `kernel[COUT][ROUT][CIN][RIN][3][3]` 展开缓存约占 `1152 BRAM`
2. `padded_frame` 约占 `128 BRAM`
3. `input_after_smooth` 约占 `64 BRAM`

也就是说，在第一轮结构里：

1. 最致命的问题不是 DSP
2. 不是 LUT
3. 而是权重展开带来的片上存储爆炸

这一点很重要，因为它直接决定了优化方向：

1. 不能再优先追求并行度
2. 必须先解决权重表示与存储方式

## 4.4 Layer1 的第二轮优化：紧凑 7 邻域权重表示

针对上述瓶颈，本轮对 `layer1` 的关键修改是：

1. 不再构造完整 `kernel[COUT][ROUT][CIN][RIN][3][3]`
2. 保留原始 `weight[COUT][CIN][RIN][7]`
3. 保留 `kernel_expansion_idx`
4. 在 MAC 循环中按需从 7 邻域权重映射到对应的卷积位置

这一点本质上就是从“显式 3x3 展开权重”切换为“紧凑 7 邻域权重表示”。

其理论意义在于：

1. icosahedral 卷积的有效邻域本来只有 7 个
2. 3x3 核只是为了复用标准卷积访问模式的中间表示
3. 如果在硬件中仍然存完整 3x3 展开结果，会额外引入：
   `Rout` 维复制
   稀疏位置零填充
   多维缓存复制

从数学上看，权重存储从：

1. `O(Cout * Rout * Cin * Rin * 9)`

压缩到：

1. `O(Cout * Cin * Rin * 7)`

这不仅仅是工程优化，更是一个“根据几何卷积实际稀疏结构重写硬件数据表示”的算法级优化。

## 4.5 Layer1 的结果

第二轮优化后的 HLS 结果：

1. Estimated Clock：`4.498 ns`
2. BRAM_18K：`192 / 890`
3. DSP：`11 / 840`
4. FF：`12715 / 407600`
5. LUT：`12524 / 203800`

相对第一轮结果：

1. BRAM：`1344 -> 192`
2. LUT：`15809 -> 12524`
3. FF：`13461 -> 12715`
4. DSP：保持 `11`

功能验证保持通过：

1. Max Error：`1.23978e-05`
2. RMSE：`1.00145e-06`
3. 结论：`PASS`

这说明 `layer1` 已经从“明显不可落地”进入“资源可接受、结构可继续优化”的阶段。

## 5. 为什么前两层的优化具有论文价值

从毕业论文视角看，前两层的工作价值不在于“写出了两段 HLS 代码”，而在于完成了以下三层递进：

## 5.1 从功能验证到资源驱动优化

最初的实现强调中间层保留与 Python 对齐，这保证了：

1. 卷积正确
2. 顶点平滑正确
3. Padding 正确
4. 权重展开正确

但在 HLS 中，验证友好结构未必资源友好。于是又进一步完成了从“验证型实现”到“资源型实现”的转化。

## 5.2 从标准卷积思维到几何卷积思维

普通二维卷积硬件常常默认：

1. 固定规则 3x3 窗口
2. 稠密卷积核
3. 标准平面行缓冲

而这里的 icosahedral 卷积不同：

1. 邻域不是普通笛卡尔平面邻域
2. 权重在不同旋转方向上存在映射关系
3. 有效核本质上是稀疏的 7 邻域核，而不是稠密 3x3 核

因此，本项目的优化并不是单纯“套标准 CNN 加速模板”，而是必须显式利用几何卷积本身的结构特征。

## 5.3 从单层优化到可推广架构

`layer0` 的意义在于建立：

1. 正确的数据流基线
2. 正确的顶点处理基线
3. 部分融合的实现模板

`layer1` 的意义在于证明：

1. 当输入/权重维度扩大后，必须改变权重表示方式
2. 必须从“缓冲驱动设计”转向“结构驱动设计”

这正是论文中最能体现“优化工作量”和“架构思考深度”的部分。

## 6. 最终高性能架构方案

如果目标不是仅完成前两层，而是面向后续更深层甚至整网部署，则建议采用如下最终高性能架构。

该架构不是简单的“完全仿照 layer0”，也不是一开始就激进地做全流式，而是融合 `映射方案.md` 中的多种思路，形成适合本网络的混合映射方案。

## 6.1 总体方案：混合映射

最终建议采用：

1. 部分映射（Partial Mapping）
2. 空间并行 + 分块映射（Spatial Parallel + Tile Mapping）
3. 层内部分融合（Partial Fusion）
4. 层间流水（Layer Pipeline Mapping）

不建议直接采用：

1. 全局一次性全并行展开
2. 全局一次性全流式融合

因为那样虽然理论上吞吐高，但工程复杂度、调试复杂度和资源风险都会迅速升高。

## 6.2 Layer0 的定位

`layer0` 推荐继续保持当前模式，作为轻量前端特征抽取层：

1. 采用当前“部分融合”结构
2. 保持低 BRAM、低时延
3. 作为整网数据流入口

原因是：

1. `layer0` 当前资源占用已经很低
2. 再激进优化带来的收益有限
3. 保留较清晰结构更利于整网联调

## 6.3 Layer1 及后续深层的高性能核心

真正的高性能重点应放在 `layer1` 及更深层，因为这些层才是主要计算热点。

建议架构为：

1. `IC/OC tiling`
2. 紧凑 7 邻域权重表示
3. 局部 partial sum 累加
4. `smooth + pad + conv` 细粒度流式融合
5. tile 级双缓冲

其核心思想是：

1. 不再处理整个 `Cin`、整个 `Cout`
2. 每次只处理一个 `Cin_tile x Cout_tile`
3. 每个 tile 内部使用局部缓冲与局部累加
4. 通过多轮 tile 叠加完成完整输出

## 6.4 建议的数据流

推荐的最终层内数据流如下：

```text
input feature stream
    -> vertex smoothing micro-stage
    -> pad/reorder micro-stage
    -> local tile buffer
    -> compact 7-neighbor MAC array
    -> partial sum accumulator
    -> output smoothing / writeback
```

其中，最关键的不是单个模块，而是数据组织方式：

1. 权重不做完整 3x3 展开缓存
2. 输入不保留整帧级大缓冲
3. 只保留 tile 级与窗口级缓冲
4. 输出采用分块累加后写回

## 6.5 复杂度优势

### 权重存储复杂度

普通完整展开方式：

1. `O(Cout * Rout * Cin * Rin * 9)`

紧凑 7 邻域方式：

1. `O(Cout * Cin * Rin * 7)`

对 `layer1` 而言，前者与后者的存储量差异已经足以决定是否能上板。

### 激活缓存复杂度

整帧缓存方式：

1. `O(Cin * Rin * Charts * (H+2) * (W+2))`

分块流式方式：

1. `O(Cin_tile * Rin * Charts * H_buf * W_buf)`

其中 `H_buf` 与 `W_buf` 只需覆盖局部计算窗口，而不需要覆盖整层输入。

### 计算阵列扩展复杂度

全展开并行方式：

1. 资源随 `Cin * Cout * Rin * Rout` 近线性放大

分块并行方式：

1. 资源主要由 `Cin_tile * Cout_tile` 决定
2. 时延通过 tile 数量线性增加

这就形成了论文中非常重要的一点：

1. 资源与时延之间是可控权衡，而不是被动失控扩展

## 6.5.1 可直接写入论文的复杂度公式

为便于在论文中统一表述，定义如下符号：

1. `T`：时间帧数
2. `Cin`：输入通道数
3. `Cout`：输出通道数
4. `Rin`：输入旋转通道数
5. `Rout`：输出旋转通道数
6. `Nc`：chart 数，本文中 `Nc = 5`
7. `H, W`：单个 chart 的空间尺寸
8. `Keff`：有效邻域权重点数，本文中 `Keff = 7`
9. `Kt`：显式展开后的卷积核点数，若按 3x3 展开则 `Kt = 9`
10. `CIT`：输入通道 tile 大小
11. `COT`：输出通道 tile 大小

### 1. 前向计算复杂度

对于 icosahedral 卷积层，若按有效 7 邻域计算，则总乘加复杂度可写为：

```text
Ops_conv = T * Nc * H * W * Cout * Rout * Cin * Rin * Keff
```

若采用显式 3x3 展开表示，则计算访存形式虽然是 3x3，但有效运算仍只来源于 7 个非零邻域，因此从算法角度更合理的表达仍应使用 `Keff = 7`。

对本项目前两层：

1. `layer0`：
   `Ops_layer0 = T * Nc * H * W * 32 * 6 * 1 * 1 * 7`
2. `layer1`：
   `Ops_layer1 = T * Nc * H * W * 32 * 6 * 32 * 6 * 7`

因此：

```text
Ops_layer1 / Ops_layer0 = 32 * 6 = 192
```

这说明 `layer1` 相比 `layer0` 的主要增长不在空间尺度，而在通道维与旋转维的组合扩张。

### 2. 权重存储复杂度

若采用显式 3x3 展开 kernel，则权重存储复杂度为：

```text
M_kernel_dense = O(Cout * Rout * Cin * Rin * Kt)
               = O(Cout * Rout * Cin * Rin * 9)
```

若采用紧凑 7 邻域权重表示，则：

```text
M_kernel_compact = O(Cout * Cin * Rin * Keff)
                 = O(Cout * Cin * Rin * 7)
```

两者之比可写为：

```text
M_kernel_dense / M_kernel_compact = (Rout * 9) / 7
```

当 `Rout = 6` 时：

```text
M_kernel_dense / M_kernel_compact = 54 / 7 ≈ 7.71
```

这说明仅从理论存储规模看，显式展开方式就比紧凑 7 邻域方式高约 `7.71` 倍；若再考虑 BRAM 端口复制、分块对齐和零值填充，实际硬件代价会更高。

### 3. 激活缓存复杂度

若采用整帧 padded 缓存，则激活缓存规模约为：

```text
M_act_full = O(Cin * Rin * Nc * (H + 2) * (W + 2))
```

若采用分块流式方式，仅保留 tile/窗口级缓存，则：

```text
M_act_tile = O(CIT * Rin * Nc * Hbuf * Wbuf)
```

其中：

1. `Hbuf` 为局部窗口高度
2. `Wbuf` 为局部窗口宽度
3. `Hbuf << H + 2`
4. `Wbuf << W + 2`

因此在深层卷积中，激活缓存可以通过 tile 设计从“与整层输入规模线性相关”压缩到“与局部计算窗口相关”。

### 4. 分块映射下的时延模型

若采用 `IC/OC tiling`，则 tile 数量分别为：

```text
NIT = ceil(Cin / CIT)
NOT = ceil(Cout / COT)
```

则总时延可近似写为：

```text
Latency_total ≈ NIT * NOT * Latency_tile + Overlap_control
```

其中 `Latency_tile` 由 tile 内 MAC 阵列规模决定，`Overlap_control` 表示 tile 切换、流水重叠和写回控制开销。

这一定性公式的意义在于：

1. 资源主要由 `CIT * COT` 决定
2. 时延主要由 `NIT * NOT` 决定
3. 资源与时延之间形成显式可调的设计权衡

### 5. 资源模型的工程表达

对于论文中的工程分析，可将 BRAM、DSP、LUT 的主导项写为：

```text
BRAM_total ≈ BRAM_weight + BRAM_input_buffer + BRAM_output_buffer + BRAM_psum
DSP_total  ≈ PE_mac
LUT_total  ≈ LUT_ctrl + LUT_index + LUT_mux + LUT_pe
```

进一步可细化为：

```text
BRAM_weight       ∝ compact_weight_cache or dense_expanded_kernel_cache
BRAM_input_buffer ∝ CIT * Rin * Nc * Hbuf * Wbuf
BRAM_psum         ∝ COT * Rout * Nc * Htile * Wtile
DSP_total         ∝ parallel_mac_lanes
```

若采用完整展开 kernel，则 `BRAM_weight` 成为主导项；若改为紧凑 7 邻域权重，则 `BRAM_input_buffer` 与 `BRAM_psum` 成为下一阶段主要优化对象。

### 6. 本项目前两层的复杂度启示

对 `layer0`：

1. 通道维较小，主要矛盾在中间缓冲组织
2. 因此优化重点是去除验证型中间数组

对 `layer1`：

1. 通道维和旋转维急剧增大
2. 主要矛盾转化为权重展开和片上存储爆炸
3. 因此优化重点必须从“删中间缓冲”升级到“重写权重表示与数据流”

## 6.6 推荐的最终工程实现路线

建议整网架构分三层推进：

### 第一层：稳定基线层

1. `layer0` 继续采用当前实现
2. `layer1` 保持当前去掉完整 kernel 缓存后的结构

目标：

1. 先形成稳定的前两层可综合、可验证基线

### 第二层：高性能计算核层

1. 将 `layer1` 升级为 `IC/OC tiling + 紧凑 7 邻域权重`
2. 为后续深层共享同一套卷积核模板

目标：

1. 将“面向单层的优化”转化为“面向多层复用的高性能核”

当前实验也已经说明这一点具有现实意义：

1. `layer1` 已完成第一版 `IC/OC tiling` 实现并通过 HLS 综合
2. 该版本证明了参数化分块卷积核在本网络中的可行性
3. 但由于引入 tile 级 `psum` 局部缓存，短期内未必继续降低 BRAM

这正体现了工程实现中的一个重要事实：

1. `tiling` 的首要价值是建立可扩展、可复用的计算组织方式
2. 它不一定在第一版实现中立刻带来最优资源结果
3. 只有在继续优化 `psum`、输入窗口与写回策略后，tiling 的结构优势才会完全释放

### 关于 `IC/OC tiling` 的直观解释

若用最简单的话来描述，`IC/OC tiling` 的含义是：

1. 不再一次性处理整层全部输入通道 `Cin`
2. 不再一次性处理整层全部输出通道 `Cout`
3. 而是把大卷积拆成很多“小通道块”分批完成

例如，对 `layer1` 而言，原始卷积相当于一次处理：

1. `Cin = 32`
2. `Cout = 32`

若采用 `IC_TILE = 8`、`OC_TILE = 4`，则硬件每次只处理：

1. 8 个输入通道
2. 4 个输出通道

一个 tile 计算完成后，先将部分和保存在局部缓冲中，再继续处理下一个输入通道 tile，最后再写回完整输出。

因此，`IC/OC tiling` 的本质并不是改变卷积数学本身，而是改变硬件处理卷积的组织方式：

1. 从“一次性整层并行计算”
2. 变为“分块迭代 + 局部累加 + 最终合并”

### 与“通用卷积块复用”的关系

这与你之前接触过的“设计成通用块然后调用”的理念本质一致，只是在 FPGA 中应更准确地描述为：

1. 构建一个参数化卷积计算核
2. 通过不同 tile 的输入、权重和控制参数重复驱动该计算核
3. 让同一套硬件在时间上复用，而不是为每一层复制一整套独立结构

从本网络结构看，这一理念在不同层上的体现程度不同：

1. `layer0` 可以体现，但不典型
   因为 `Cin = 1`、`Rin = 1`，规模较小，更适合作为前端特化层
2. `layer1` 开始具备明显意义
   因为通道维和旋转维都已经扩大，分块开始能够显著影响资源组织
3. `layer2-5` 最适合体现“通用块复用”
   因为这些层在结构上是重复 block，通道规模一致、空间尺度相近，非常适合共享同一套参数化 HLS 卷积核

因此，从论文角度可以这样概括：

1. `layer0` 是前端特化实现
2. `layer1` 是从特化层过渡到通用块设计的第一个实例
3. `layer2-5` 则是参数化卷积核复用思想最充分体现的主干区域

### 第三层：层间流水层

1. 前后层通过片上流接口相连
2. 使用双缓冲或 ping-pong buffer 连接层间数据流
3. 将外部存储访问尽量压缩到层组边界

目标：

1. 从单层 HLS 优化，上升到系统级吞吐优化

## 7. 可直接用于论文的技术贡献表述

从论文写作角度，前两层优化可以概括为以下几个贡献点：

1. 提出并实现了一套适配 icosahedral 卷积的 HLS 数据流重构方法，使特殊拓扑卷积在 FPGA 上具备可综合、可验证基础。
2. 通过移除验证型大中间缓冲，实现了从“逐层对齐结构”到“面向硬件映射结构”的转化。
3. 针对深层输入通道扩张导致的 BRAM 爆炸问题，引入基于紧凑 7 邻域权重表示的卷积实现方式，显著降低片上存储需求。
4. 构建了从 `layer0` 到 `layer1` 的渐进式映射路线，为后续多层共享的高性能分块流式架构提供了实验依据。
5. 提出适用于本网络的混合映射方案，即“部分映射 + 空间并行 + 分块流式 + 层间流水”，兼顾资源约束、可验证性与最终吞吐性能。

---

## 8. 结论

前两层的工作已经表明：

1. `layer0` 适合作为低成本、稳定的前端实现模板。
2. `layer1` 不能简单照搬 `layer0`，必须引入更深层次的权重表示优化与分块流式思想。
3. 真正高性能的整网实现，不应建立在“完整展开 + 完整缓存”的思路上，而应建立在“结构感知的数据表示 + 可控分块并行 + 层间流水”之上。

因此，从毕业论文角度，前两层的优化工作并不是零散的调参过程，而是一条完整且有技术深度的架构演化路径：

1. 从正确性出发
2. 以资源瓶颈为驱动
3. 最终走向高性能混合映射架构

这条路径本身，就是论文中最值得强调的优化主线。
