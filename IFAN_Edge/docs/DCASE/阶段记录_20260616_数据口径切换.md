# DCASE Stereo Azimuth-Only 阶段记录：从严格微调到数据口径切换

## 当前结论

到目前为止，DCASE 独立分支已经完成了三类尝试：

- 结构对齐：从 Stage 1 的 `3D 输出头 + folded-azimuth 水平目标向量`，切到 Stage 2 的真正 `azimuth-only / sin-cos` 输出头。
- 严格口径微调：在 `strict` speech-only 单源子集上继续尝试 channel-swap、边缘方位加权和 tail 指标治理。
- 数据口径放宽与重构：从 `strict` 切到 `non-strict`，再进一步构建 `IFAN-adapted` 的重采样训练 manifest。

当前判断是：

- 最有效的结构性改动是 Stage 2 的 `azimuth-only` 头。
- 在 `strict` 子集上的后续微调收益非常有限，已经接近平台。
- 下一阶段的主工作重心应从“继续调 loss / 轻增强”切换到“直接改造训练数据分布和训练清单”。

## 结果时间线

### 1. Zero-shot 基线

使用 LOCATA 主线 checkpoint 直接迁移到 DCASE `locata_like_devtest_strict`：

- overall `DOA error (deg) = 44.9631`

这一步的意义是确认：

- LOCATA `benchmark2 / 3D DOA` 口径直接迁移到 DCASE stereo / folded-azimuth 任务时误差较大
- 后续所有独立 DCASE 训练结果都应与它比较

### 2. Stage 1：stereo frontend + folded-azimuth 目标对齐，保留 3D 输出头

关键 run：

- `run10_bg`
- `run80_bg`

结果：

- 10 epoch：overall `40.9836`
- 80 epoch：overall `37.4179`

说明：

- 仅对齐 stereo 前端和 folded-azimuth 目标，就已经显著优于 zero-shot
- 但继续加长轮次后收益开始明显递减
- moving 子集没有随着长轮次同步稳定改善

### 3. Stage 2：真正的 azimuth-only / sin-cos 输出头

关键 run：

- `stage2_azimuth_only_run30_bg`

结果：

- best validation `27.8895`
- test overall `29.3776`
- static `29.3799`
- moving `29.2652`

相对 Stage 1 best 80 epoch：

- overall：`37.4179 -> 29.3776`

这一步是当前最成功的结构升级，说明：

- DCASE stereo 分支最应该保留的是 `azimuth-only` 头
- 相比继续在 3D 输出头上堆轮次，直接切对输出参数化更有效

## Stage 2.5A：strict 子集上的 tail / edge 微调

### 做过什么

在 Stage 2 best checkpoint 基础上，我们加入了：

- tail 指标：
  - `p75 / p90 / p95`
  - `>=45 / >=60 / >=90 deg` 计数
  - by-angle-bin 诊断
- `channel-swap` 训练增强
- `edge-weighted` folded-azimuth sin/cos loss

关键 run：

- `stage2_5_swap_edge15_ft10`
- `stage2_5_swap_only_ft10`
- `stage2_5_edge15_only_ft10`

### 结果

对比 Stage 2 baseline：

| Run | Best Val | Test Overall |
| --- | ---: | ---: |
| Stage 2 baseline | `27.8895` | `29.3776` |
| Stage 2.5 swap+edge15 | `28.4664` | `29.4908` |
| Stage 2.5 swap only | `28.5194` | `29.3449` |
| Stage 2.5 edge15 only | `27.9549` | `29.4023` |

观察：

- `swap only` 最接近 baseline，但没有形成明确提升
- `edge15 only` 几乎持平略差
- `swap + edge15` 综合结果也略差
- 这些改动都没有超过 Stage 2 baseline

结论：

- `strict` 子集上的问题不像是继续调损失就能解决
- 该方向最多只能做小幅尾部整理，不足以打开新空间

## 数据口径问题：为什么 strict 容易卡住

我们回看现有 manifest 统计，发现 `strict` 口径过于保守：

### strict speech-only

- train 总数：`1844`
- moving：`53`
- static：`1791`

对应 devtest strict：

- test 总数：`727`
- moving：`15`
- static：`712`

这意味着：

- moving 样本规模太小
- 训练分布几乎被静态片段主导
- 对角度边缘和更复杂 clip 的覆盖也不足

### non-strict speech-only

如果只去掉 `single_source_id` 约束，使用 `locata_like`：

- train 总数：`2829`
- moving：`1035`
- static：`1794`

对应 `locata_like_devtest`：

- test 总数：`1054`
- moving：`340`
- static：`714`

这说明：

- 我们原来不是“moving 学不会”
- 更像是“strict 清单把真正有运动的信息切掉太多”

## non-strict speech-only 尝试

关键 run：

- `non_strict_speech_run20_bg`

结果：

- best validation `30.0514`
- test overall `32.2351`
- moving `39.3882`
- static `28.8288`

解释：

- 单纯把数据从 `strict` 放宽到 `non-strict speech-only`，并没有自动带来更好的整体结果
- 但它确实暴露出 moving 和更复杂 clip 比 strict 要难得多
- 这一步的价值不是追求立刻更高分，而是证明：
  `strict` 结果不能代表更接近 DCASE 本体的分布

## 当前在跑的主线实验

当前主线已经切换为：

- 配置：
  `IFAN_Edge/configs/dcase_stereo_azimuth_only_ifan_adapted_all_classes_balanced.toml`
- 训练 manifest：
  `datasets/DCASE2025_Task3/ifan_adapted_all_classes_balanced/manifest_all.csv`
- 测试 manifest：
  `datasets/DCASE2025_Task3/locata_like_all_classes_devtest/manifest_all.csv`

这条线的目标不再是 strict 小切片上的小幅微调，而是：

- 让训练分布更均衡
- 让 moving 样本不再稀缺
- 让角度边缘 bin 不再长期欠采样
- 检查更接近 DCASE 本体分布时，IFAN azimuth-only 结构是否还能继续工作

## 到目前为止的统一判断

### 已被验证有效的点

- stereo frontend 对齐有效
- folded-azimuth 目标对齐有效
- azimuth-only / sin-cos 输出头有效

### 已被部分证伪的点

- 继续在 strict 子集上做轻量 loss 微调，不足以带来明显新提升
- 单纯 non-strict speech-only 放宽，并不会自动变好

### 当前最值得继续的方向

- 直接重构训练清单分布
- 从 `speech-only / strict` 小切片转向更大、更难、更均衡的 all-classes 分布
- 在此基础上再看是否需要引入真正的 DCASE-conditioned 仿真数据

## 下一步建议

当前阶段结束后，优先顺序建议如下：

1. 先把 `ifan_adapted_all_classes_balanced` 这条 run 跑完并观察 validation / devtest。
2. 若这条线仍明显无效，再进一步引入真正的 synthetic / simulation 数据，而不是回头继续调 strict loss。
3. 若这条线有效，再考虑：
   - 加 onscreen ratio 过滤版本
   - 加 speech-only adapted 版本
   - 加 DCASE-conditioned stereo synthetic 混合训练

一句话总结：

到 `2026-06-16` 为止，这条 DCASE 分支已经完成了从“结构对齐”到“strict 微调”，再到“数据集重构”的切换。当前主线不再是 strict 上的微调，而是直接改训练数据分布，使其更贴近 IFAN 的学习需求。
